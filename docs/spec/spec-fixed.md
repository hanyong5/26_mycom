# mycompany 홈페이지 요구사항 설계서

## Context

`docs/spec/spec-original.md`의 원본 요구사항은 다음과 같이 간략하게 기술되어 있다:

> 회사홈페이지 개발 — 회원관리(admin/user), 제품소개, 게시판, 문의하기

현재 프로젝트는 **개발 진행 중** 상태다. `CLAUDE.md`에 IA, DB 스키마, 라우팅 구조가 정의되어 있으며, Supabase MCP 연결이 완료되어 있다. 이 문서는 원본 요구사항을 기반으로 도출한 20개 기능 요구사항과 에지케이스를 포함하며, 구현 확정 사항은 지속적으로 반영한다.

## 에지케이스 설계

### AUTH 에지케이스

| EC-ID | 시나리오 | 예상 처리 |
|-------|---------|---------|
| EC-A01 | 이미 가입된 이메일로 재가입 시도 | Supabase 에러 캐치 → "이미 사용 중인 이메일입니다" 인라인 메시지 |
| EC-A02 | 비밀번호 8자 미만 / 숫자·영문 미포함 | 클라이언트 유효성 검사 → 제출 차단, 조건 안내 |
| EC-A03 | 잘못된 이메일/비밀번호로 로그인 | "이메일 또는 비밀번호가 올바르지 않습니다" (구체적인 원인 미노출) |
| EC-A04 | 세션 만료 상태에서 보호 페이지 접근 | `onAuthStateChange` 감지 → 자동 로그아웃 처리 → `/auth/login` 리다이렉트 |
| EC-A05 | 일반 유저가 admin 전용 URL 직접 접근 (예: `/contact/my` 전체 조회) | RLS 정책으로 DB 레벨 차단 + 프론트 역할 확인으로 이중 방어 |

### BOARD 에지케이스

| EC-ID | 시나리오 | 예상 처리 |
|-------|---------|---------|
| EC-B01 | 빈 제목 또는 빈 내용으로 게시글 작성 시도 | 폼 제출 차단 + 필드별 에러 메시지 표시 |
| EC-B02 | 존재하지 않는 게시글 ID(`/board/9999`) 접근 | Supabase 빈 결과 감지 → "존재하지 않는 게시글입니다" + 목록으로 이동 버튼 |
| EC-B03 | 타인의 게시글 수정 URL 직접 접근 (`/board/:id/edit`) | 작성자 확인 후 불일치 시 403 처리 → 목록으로 리다이렉트 |
| EC-B04 | 게시글 작성 중 세션 만료 | 제출 시 401 에러 감지 → 작성 내용 로컬 저장 후 로그인 페이지 이동 (내용 보존) |
| EC-B05 | XSS 시도 (제목/내용에 `<script>` 삽입) | React의 기본 이스케이프로 방어. dangerouslySetInnerHTML 미사용 |
| EC-B06 | 총 게시글이 0개일 때 목록 페이지 접근 | 빈 상태 UI ("아직 작성된 게시글이 없습니다") 표시 |
| EC-B07 | 존재하지 않는 페이지 번호(`?page=999`) 접근 | 마지막 페이지 또는 1페이지로 fallback |

## 데이터베이스 스키마 (생성 예정)

### 생성 순서
1. `profiles` — auth.users 트리거 연동
2. `posts` — profiles FK
3. `inquiries` — profiles FK
4. `products` — 독립 테이블

### RLS 정책 요약

| 테이블 | SELECT | INSERT | UPDATE | DELETE |
|-------|--------|--------|--------|--------|
| profiles | 전체 허용 | 본인만 | 본인/admin | 본인/admin |
| posts | 전체 허용 | 인증 사용자 | 본인/admin | 본인/admin |
| inquiries | 본인/admin | 인증 사용자 | 본인/admin | 본인/admin |
| products | 전체 허용 | admin만 | admin만 | admin만 |

## 검증 방법

- **인증 흐름**: 회원가입 → 이메일 확인 → 로그인 → ProtectedRoute 접근 → 로그아웃 순서로 E2E 확인
- **권한 검증**: admin 계정과 user 계정 각각으로 모든 라우트 접근 테스트
- **에지케이스**: 각 EC-ID별 시나리오를 브라우저에서 직접 재현
- **DB 레벨 보안**: Supabase MCP `execute_sql`로 RLS 정책 우회 시도 확인
- **반응형**: 브라우저 DevTools 모바일 뷰(375px)에서 GNB 햄버거 메뉴 동작 확인
